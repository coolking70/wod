# Workspace evidence and development rules

- Preserve CATALOG.v12 and every later append-only catalogue, all base/delta/manifests and maintenance dependencies, source/Pages bundle chains, six retained old refs, and unique evidence. Never run GC/prune or force-push history.
- Capture commands, including ad-hoc Playwright/image/measurement helpers, must use `node scripts/run-evidence.mjs --label NAME --parent /workspace/wod-evidence/VERSION/runs -- node SCRIPT`. The launcher prints the unique run and output directories. Helpers must use `process.env.WOD_EVIDENCE_DIR`; do not hardcode old evidence paths or add shell `>` redirections to old logs.
- A capture root is single-use. Reruns, failures, interrupted runs and changed source require a fresh run directory. Never remove a prior claim or use an old root/token to resume. Capture entrypoints already load `capture-bootstrap.cjs`; new entrypoints must do so before other imports and be added to `scripts/capture-entrypoints.json`.
- Screenshot, JSON, copy, stream and write-capable file outputs are exclusive. Do not bypass this by writing through native commands, opening existing descriptors, removing originals, or catching an overwrite refusal and retrying the same target. External/Python writers must also use newly claimed directories and exclusive `x`/`xb` creation. For native publication use an atomic no-replace operation. This is an operational guard, not an OS or network sandbox.
- The browser coordinators share fixtures inside one owned run. Keep original behavioral assertions. Existing append-only JSONL logs and immutable progress snapshots are supported; `browser-progress.json` is explicitly a mutable live pointer to retained snapshots, never the only evidence.
- For Node tests use the same launcher with `-- node --test ...`. It captures stdout/stderr exclusively and strips WOD environment variables from the test runner. Tests control their own temporary fixtures; capture entrypoints launched by tests still protect their own outputs.
- Legacy art exporters trying to write published `dist` assets must fail closed. Generate candidate assets in the new run output, review them, then explicitly copy approved files as a version-controlled implementation change. Never overwrite evidence to publish an asset.
- Record original gaps honestly: v186 two early PNG/metrics, v190 first temporary timestamp export, v199 first-source inverse reconstruction, v201 six early visible-map PNG/metrics overwrite, and older ID/time byte gaps. Cold remeasurements are new evidence and cannot be described as recovered original images.
- Before complete milestone gates, measure physical capacity including growth, failure reruns, restore operations and a reserve. Source pushed to GitHub does not back up unique test evidence. Retire duplicates only after durable exact-byte independent cold recovery and required full-root checks. Current main/Pages and development branch must be reported separately. Permanent supply economy remains pending.
