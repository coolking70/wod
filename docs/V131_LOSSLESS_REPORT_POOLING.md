# v0.131 完整战报无损压缩

v130真实存档已有四份关键报告，占743652/800000编码字符，新47报告再按普通gzip需138388，因容量不足不能收藏。本阶段处理这个已复现问题：新收藏可复用完全相同的单位状态，保留全部事件和原始数值；不扩大容量、不自动改写/删除旧收藏，不改变战斗、奖励、成长或补给。

## 无损表示与还原

事件里的units数组会重复大量完全相同的单位快照。新表示使用按JSON字节相同的状态字典与整数引用；事件顺序、角色顺序、生命/法力、装备后属性、状态组件、召唤、阶段及来源、原始详情和结算全部保留。只复用保存表示，不推断中间过程或删减状态。

freezeReport先按既有完整报告校验和12MB原文上限检查，计算原JSON长度/SHA，再同时尝试普通gzip与状态字典gzip。只有实际base64更小时才选新编码，字典本身更大或无收益仍用原普通gzip；一条压缩流超过单份编码上限，不阻止另一条有效较小结果。两者均超限仍拒绝。外层快照encoding明确区分gzip-base64与gzip-units-v1-base64，新编码多packedBytes；不修改旧四份编码、字节或校验值。

读取先按packedBytes/12MB限制解压，严格检查格式版本/键、字典、引用整数/边界、20k事件/每事件40单位、重复引用、未用/重复状态及嵌套深度。根据每个状态的UTF8字节数和所有引用，**在复制重复对象之前**计算完整还原JSON预算，必须等于原rawBytes且不超过12MB；之后为每帧建立独立对象，再检查原完整JSON长度/SHA、完整报告结构和元数据/摘要。小字典不能绕过完整还原大小限制；共享引用不会让修改一个读取帧污染其他帧。

6份、总800000 base64字符、原文12000000字节、配置100000字符的现有限制均保持。旧普通gzip解码路径继续读取当前实际四份，不增加存档迁移或自动重编码。完整导出仍返回原完整报告。整档/单独公会导入继续逐份内层校验、外层校验和与写前防覆盖，失败不修改资产。
