## 为什么回到角色表现

原始`archive/M0_PLAN.md`的M2及`DEVELOPMENT_PLAN.md`的R3要求先做一名守卫的可复用动作样板；v9现有头像整体跳动与同组文字提示，尚无肢体动作。当前援护尝试、挡架检定、实际受击同时列在一组，不能从抬盾直接区分是否成功接招或免伤。本轮补这一实际阅读缺口，没有继续堆叠技能/先攻开关或复制地城。

新`expedition-guardian-motion.mjs`只消费已记录事件，原创SVG同一模型通过9个嵌套关节复用11种姿态，不是多张不一致的静态图、完整蒙皮骨骼系统、3D或AI视频。`guardian-motion.css`提供材质、关节轴及尺寸。使用浏览器Web Animations API按原事件顺序演示，所有移动都是卡片内示意，不表示角色换阵位、冲锋距离、射程或碰撞。

仅职业guardian且出发快照确实携盾者使用模型；其他职业或弓/法器等装备保留原头像。卫士剑盾有剑，圣匣重盾没有虚构剑刃，并使用不同抬盾出手动作。9关节为整体、躯干、头、左右上臂/前臂与双腿；共享同一轮廓、颜色与骨架锚点，不请求新图片或外部运行资源。只完成一个守卫程序样板，其他职业、完整美术风格统一、蒙皮与音效仍未交付。

## 所有动作以原事件为准

| 原记录 | 动作表达 | 明确边界 |
|---|---|---|
| 本人近战cast/attack | 准备出手→实际出手 | 闪避也可有一次出手，不凭动作补命中/伤害 |
| 本人辅助cast | 支援准备/抬盾 | 只有真实施放才动，未付款的skip不冒充施放 |
| intercept成功/失败 | 援护接招/伸手未及 | 失败不虚构接触或守卫承伤，仍用实际受击者 |
| 实际parry防御选择 | 挡架检定 | 付款与抬盾不等于挡开；后续受击仍演受击 |
| attack为闪避 | 挡开或闪避 | 根据实际defenseProfile.skill，不把自然回退称付费格挡 |
| attack/harm实际HP>0 | 受击−actual | 不用含溢出damage，不制造攻击者施法/额外行动 |
| 命中实际HP=0 | 稳住/实扣0 | 不把护甲或抗性结算推断为格挡成功 |
| 原down及之后HP0快照 | 倒下→保持倒下 | 不重复死亡，不因下一步或跳房恢复站立 |

纯MP损失、免疫、未尝试援护、自然回蓝、召唤他人的随从不生成守卫身体接触。原始来源eventId保留在每个动作阶段；界面单位按钮带可读动作序列，已有提示条与原事件依据继续可查。生命/法力/资源始终是当前步最后事件的原快照，不逐毫秒推导或提前写回，动作只解释一次已经完成的结算。

每组900ms/播放速度，0.5/1/2/4倍均在原1300ms/速度自动步进间隔内结束；没有新计时器、完成回调或状态存储。换步前取消旧动画，暂停、查看单位、切页面、隐藏页面时直接收束到原步结算姿态，避免残留动作影响下一步。减少动态效果偏好下不创建关节动画，仍保留静态站立/倒下、HP和原文字反馈；运行中切换也会在浏览器媒体变化事件后收束。没有额外游戏时间或战斗行动。
