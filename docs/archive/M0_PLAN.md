# 深潮远征：具体开发方案

## 产品目标

制作适合异步参与的队伍策略冒险：配置角色 → 制定战术 → 探索地城 → 观看执行 → 分析失败 → 修改配置。保留 WoD 式团队分工和资源管理，采用原创规则、角色与关卡。初期单人控制六人，用来验证系统；多人协作在核心闭环稳定后实现。

第一目标是可解释的策略决策与视觉反馈，第一轮不承诺大型内容库、付费经济或生成式视频实时演出。

## 技术决策

初步采用零依赖原生 JavaScript 模块、HTML/CSS/SVG。原因：网页直接试玩、部署简单、AI 可编辑、调试成本低。本次不复制授权不明的自动战斗仓库。规则不依赖 DOM；表现只消费事件和状态。后续只有在角色动画/场景复杂度证明需要时才切换 PixiJS、Three.js 或引擎，不为原型增加构建门槛。

模块边界：
1. 内容数据：英雄、技能、敌人、房间、事件、物品；M1 起移出引擎为独立文件并严格校验。
2. 规则模拟：输入队伍快照、战术、房间、种子与规则版本，输出状态和事件。
3. 远征流程：准备、战斗、结算、事件、下一房间、完成/失败。
4. 演出调度：动作、目标连线、状态图标、速度与时间轴；不写入模拟结果。
5. 复盘：解释触发/不触发、资源不足、目标选择、关键失败；当前仅逐行动记录。
6. 存储：M0 仅本机战术；M1 加版本化进度；多人阶段再做服务端存储。
7. 资产：离线生成、筛选、登记、压缩并打包；游戏运行不依赖生成接口。

## M0：可玩样片（本轮已实现）

- 六人固定队伍：守卫、剑士、游侠、术士、医师、诗人。
- 每人一个基础与一个特殊技能；特殊技能按条件触发，资源不足兜底基础行动。
- 可配置五类条件：每次、低血线、敌方蓄力、第一回合、关闭；三类攻击目标。
- 三战一事件：积水回廊 → 泉水二选一 → 钟楼蓄力打断 → 首领战。
- 房间间生命法力继承；恢复与强化治疗二选一。
- 可暂停、单步、1/2/4倍、直接结算；最近一战可拖动回放。
- AI 生成环境背景一张，棋子式临时角色及程序特效。
- 战术本地保存、整轮记录 JSON 导出。

验收：浏览器完成整轮、回放不重复发奖或推进房间、同种子同输入得到同结果、战术改变会影响行动、缺蓝不能施放特殊技能。数值允许教学难度，暂不做全量平衡。

## M1：让策略可解释

交付：
- 将英雄、敌人、技能、事件配置拆开，定义 schema 与规则版本。
- 多条战术规则与明确的顺序语义；选择优先级规则还是 WoD 式游标序列后，在 UI 中解释。不可隐含混用。
- 战报记录 conditionResult、reason、resourceBefore/After、targetReason；显示“为什么没治疗”。
- 每名角色伤害/治疗/护盾吸收/控制统计，关键行动跳转。
- 3–6 件有取舍的装备；不先加随机词条系统。
- 带版本的本地远征保存及导入导出；回放模式与实时远征状态彻底分离。

验收：测试者能从复盘解释一次失败，并通过一个明确改动改变结果；读档不能重复结算或丢失事件选择；已完成所有房间可切换回放。

## M2：美术生产样板

先选定统一风格、角色比例、镜头角度、环境色板。
- 只先制作一名守卫：概念图、标准参考、骨骼或动作模板、待机/攻击/受击/倒下。不得以独立相似站姿替代真正动作。
- 扩展两张独立房间图及一张泉水事件 CG；记录图层、遮挡区域与角色落脚区。
- 单个关键事件尝试 3–6 秒预生成短视频；可跳过、无视频时插画兜底。
- 整理角色与特效资产契约：锚点、方向、动作名、命中时刻、尺寸、配色、来源。
- 记录生成次数、可用率、人工修整分钟数、引擎接入分钟数、文件体积。

验收：角色身份一致、动作可读、攻击对象准确；在目标设备上无明显卡顿；增加第二个房间不需要修改核心代码。只在这条管线通过后扩展六名角色。

## M3：成长与可重复地城

- 六职业逐步扩到约 24–36 个技能和约 30–60 件装备，最终数量服从试玩反馈。
- 关卡模板＋受约束组合：空间、环境、敌群、事件；生成时验证资源和可通行/可完成条件。
- 环境必须明确标注其规则效果，视觉装饰不偷偷改变数值。
- 新增 2–3 条短地城，形成不同组队要求，不以堆高血量替代机制。
- 收集失败分布、技能使用率、恢复资源消耗、每轮决策时长。

验收：不同配置有可解释的优劣；重复挑战出现有意义的取舍；资产生产时间可预测。

## M4：异步合作

- 服务端权威模拟与结算；客户端不能自行提交胜利或奖励。
- 每名玩家管理自己的角色；出发时锁定队伍、配置、内容版本和种子。
- 准备状态、离线成员默认策略、队长出发、共享回放。
- 幂等结算、配置版本、掉线恢复与迁移。
- 小规模邀请测试后再考虑公开社交、交易及商业化。

验收：所有成员看到一致结果；重试/重连不重复奖励；配置修改只影响下一次合法出发。

## AI 的职责

开发阶段使用 AI 辅助代码、内容草稿、插画、道具概念及视频样片；所有影响战斗的机制必须落为可校验的数据和规则。运行时用已审核资产组合场景、以实际事件组织镜头。个性化纪念图可后续异步生成，不能阻塞结算。无需现在购买付费生成服务或配置密钥。

## 下一轮优先级

1. 先收集本版的战斗阅读、战术编辑、节奏反馈。
2. 解决战术原因解释与多房间回放。
3. 验证一个完整角色动画资产，再扩展内容。

避免在首次反馈前并行引入多人、海量职业、随机装备、实时视频生成四项复杂度。
