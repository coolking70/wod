# v0.121 个人演武

本阶段从v120真实1835金币、本人塞恩、两枚分诊铜签和第17次已领取状态继续。新增自己英雄的独立演武，让现有默认指令、配装和培养在失去队友后接受检验，再返回正式六人远征验证。没有新增技能、路线、装备或奖励。

## 玩家流程

公会“我的英雄与伙伴”展开“个人演武”，选择三名配置公开的本地陪练之一。演武读取**当前自己的英雄**，不读取成长/装备面板正在观察的其他队员。可自由切换本人，资产不转移。沿用公会实际装备、训练、已学课程和独立进阶；实验草稿不能授予资产或技能。

读取当前准备种子、携行量与默认预备/普通/条件救护；逐房覆盖保留在远征方案里，演武不采用。本人可以按原规则召唤，伙伴不进场、不施放或提供救护，召唤伤害也不混入本人实伤。对手有固定属性、装备、基础技能、防御与指令，沿用敌方每类60份独立临时材料和既有支付规则。全部采用原引擎与24回合上限，不额外加成或按职业调整难度。

整场预先自动结算后，以专用界面逐事件回看。显示真实生命/法力、效果、当前材料、施放费用、攻防检定和原始证据。回看不会再随机/扣费。演武无正式编号、金币、经验、装备、攻略首证或排名；临时HP/MP/材料不写回存档。正式远征待领取期间禁用新的演武。

结果仅在页面内存，刷新清除；专用`wod-personal-sparring` JSON可导出，不是准备配置、整档或奖励收据。准备/培养/装备/本人/陪练变化后保留旧结果但明确标旧；跨页面修改或删除准备记录时拒绝执行旧配置，回看和导出仍只读。

## 实现和数据边界

- `expedition-sparring.mjs`：专用API、公开陪练、实际资产/默认配置装配、单人模拟、签名和独立导出。
- `expedition-sparring-view.mjs`：专用单人回放、公开配置、实际培养/课程/进阶、过期提示。不会将单人报告送入默认六人攻略/正式结算界面。
- `expedition-guild-ui.mjs`：在既有英雄面板接入，内存状态、存储过期检查和手动事件导航；不新增顶层面板、存档键或定时器。
- `sparring-cases`/`check-v121`：固定失败→实际付费培养→正式18的可重跑证据；`browser-v121`核对完整快照和公会，而非只看胜负文字。

底层模拟需要完整准备结构，所以用既有默认框架装入实际六人数据进行合法性检查，再显式只传本人和一房固定陪练给引擎。框架中的其他五人不参加模拟；外层模式、专用UI和导出明确为个人演武，不能把框架的普通路线名当作实际演武或正式奖励目标。所有25条远征、40装备、75普通目标及旧战斗/支付/奖励公式保持。
