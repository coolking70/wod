# v0.142 前线候补与援护可读战报

单人名册此前只有学者、药师候补，前线没有同职业替补。新增可选守卫贝芮尔（beryl），沿用个人英雄＋五名伙伴、六人出战和小规模名册。完成三次普通远征结算后可支付60公会金币招募；依照已有招募规则计算结算次数，不另要求全员存活或成功。招募不自动换人。初始经验0、无永久训练、无课程或后期进阶，只有守卫初始装备；不会继承阿瑟资产。全部三位候补都招募后共九名成员，出战仍六位。

贝芮尔与阿瑟均为守卫，使用同一职业技能、自由构筑与独立后期进阶入口。基础属性总和都是79：贝芮尔力量10、体质18、智力5、灵巧9、魅力6、敏捷6、感知13、意志12。相对阿瑟为体质+2、感知+4、力量/灵巧/敏捷各−2，其余相同。同装备、相同自由专修和培养下，当前项目公式给出HP+8、MP相同、援护均值+8、挡架均值−6、攻击更低；自然先攻均值相同，不能称更慢。默认自由专修援护，预备援护后排→守势自保，普通攻击作低耗后备。这不是付费培养，也不限制阿瑟改为同样的自由专修。

援护仍需施放费用和每回合实际反应费用；成功只是接招，接着由援护者按自己的防御与生命结算，不是无敌或避免伤害计分。同技能在同一受益者上不叠加，双守卫应考虑分区，实际反应次数及法力仍有限制。新伙伴没有自动追赶经验，候补阿瑟不获得本次未出战的经验。可以换回阿瑟，也可以在实际出战者间切换自己的英雄，不锁定初始主角。

首次浏览器验收错误点击组内事件，随后发现普通完整施放详情只显示主攻击，援护子事件仅在原始记录内。新增纯显示模块expedition-interception-view：普通分组也直接展示实际援护成功/失败、原目标与实际受击者、反应实掷/均值/难度及已付MP前后值。逐条诊断仍可选原事件。程序守卫动作按职业和真实ID自动适用新角色；不补造动作接触、反事实减伤或重复结算。导入冻结报告的detail是通用对象，因此包含原数值在内的所有显示字段均转义；普通已记录数值生成的HTML逐字相同。早期统一验收子集复用此显示转义前的通过记录，相关守卫125/新142及最终完整回归使用最终代码，具体范围见验证收据。两轮失败脚本、日志、截图与四原始键全部留存。
