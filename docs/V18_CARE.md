# v0.18 受击与救护时序

本版只修改只读投影与界面，不改变战斗规则、随机流程或配置格式。

## 操作

点击战场正式队员，在角色检查区下方展开“受击与救护时序”。仅显示当前房间、截至当前回放快照的最近12条相关记录，并显示已发生总数。切换房间不会混入上一房间记录。

受击行合并实际防御技能/投点、攻击投点、护甲、抗性、实扣与HP前后值；治疗和生命药匣独立列出；药师已执行的施放、道具、等待和空过行动穿插展示。治疗别人时显示实际对象。数据没有完整记录所有未触发治疗的条件，因此不推断“为何没有治疗”。

守灯结算点击某人的倒下记录，会选中该人并打开面板。点击时序行回到对应行动，后续尚未发生的记录消失。合并模式以整次施放结束快照为界；逐条诊断模式以单条事件为界。时序不是完整战报的替代品。

## 敌人辨识

根据敌人模板的可用攻击技能类型标识近战、远程、法术或复合，召唤物单列。标识是敌人攻击能力分类，不承诺其当前必然使用某种攻击。文字、符号与头像边框共同区分，不依赖单一颜色；继续使用已有头像，本版未生成独立敌人立绘。

## 验证

124项测试通过。覆盖前缀不泄露倒下结果、同房范围、HP与防御投点对齐、治疗投影、数量限制、无副作用、非法选择、三类敌人及复合首领/召唤标识。

浏览器：守灯原始队形、种子1，露弥第三房倒下。时序显示第一回合闪避后治疗伊芙，第二回合HP74→35后治疗维斯，第三回合HP35→0。回退第二回合后只有前三条，返回第一房进场则无历史记录。结算倒下入口正确选中露弥；敌方标识分别为近战、法术、远程。

该例显示药师自己的生命风险与治疗他人的时序，不单独证明治疗策略错误：其他目标、阈值、资源、防御与先攻都应结合完整战报和对照分析。

后续可增加治疗决策的结构化诊断记录（检查对象、阈值、资源与未执行原因），再做可靠的“为什么没有治疗”解释；应避免由界面猜测模拟器没有记录的原因。
