## 后续执行节奏

每个有意义的开发阶段先完成实现和适用验证，再本地提交、正常推送独立功能分支并核验远端SHA；已有远端分支有差异时先读取和比较，不覆盖、不强推。推送失败或结果不确定时，先保留日志、只读核对实际状态，不改凭据或绕过保护。

以完整功能里程碑为主，每3–5个完成的小版本评估一次main归并；本次v137为首次归并，下一检查窗口为v140–142，必要的连贯功能完成时也可提前评估。版本数量不是合并成功条件，更不是增加小功能凑版本的理由。合并门禁包括最新远端main、干净工作树、差异与冲突检查、相同代码的完整测试/适用浏览器验收、存档和重复领奖边界，以及可恢复证据。未变代码的已校验收据可复用，但须明确哪些检查本次重跑。存在失败、冲突、远端新工作或重大设计风险时停止合并；不强推、不绕过保护。

只清理明确合入main且提交可恢复的旧分支，保留main、当前工作分支与最近必要里程碑；先保存名称/旧SHA，删除前再次核对。删除分支不会自动释放Git对象空间，不运行GC/prune来追求容量。

正式源码在GitHub及最近完整bundle中已核实后，可清理完全可重建的旧源码ZIP/bundle/补丁。先核对每份内容、提交覆盖及原校验，未知内容保留。仓库外证据、图像、失败案例、云端独有旧提交和未备份内容不因Git分支已推送而删除。
