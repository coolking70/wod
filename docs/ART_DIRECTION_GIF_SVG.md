# 后续美术试作：动作GIF与SVG场景/道具

用户方向：后续利用可用的GIF动画生成能力增强表现，背景和道具尽可能用SVG以改善加载；必须实测，不预设SVG一定更快。此计划不打断171的修复验收，不改变结算、数据格式或既有角色身份。

## 已核实的本会话能力

- 已检索全部65项云技能、执行环境技能（0项）及当前工具目录，未发现适用于本网页游戏的专用GIF生成技能。动画宠物技能限定ChatGPT宠物，Unity技能也不适用于这个原生网页项目，不能冒用。
- 可调用image_gen生成/编辑静态图，但工具没有承诺原生GIF输出。云环境已有Pillow、ffmpeg和ImageMagick，可把经检查的帧编码为GIF；这是生成帧＋本地编码流程，不是原生视频/GIF生成能力。未声称已经生成了GIF。
- 当前13张PNG共39244295字节，单张约2.7–3.2MB；背景为暗色海潮/修道院绘制风格。守卫/游侠已有原创程序SVG关节图形与事件动作，必须先检查实际显示，再选择与人物、配色和场景统一的方案。

## 首批小范围试作

1. 角色动作优先贝芮尔/守卫的援护接招或挡架，沿现有轮廓和装备，取一次实际事件做短动作。先比较已有程序SVG、静态poster与GIF，不为使用GIF替换表现更好的实时图形。若使用生成帧，逐帧检查人物一致、装备、姿态和透明边缘，不能将一次挡架动画暗示为必定免伤。
2. 道具先选邮铃或符纸，背景先选邮路桥面/夜海一处。SVG使用少量分层轮廓、统一暗蓝/金色，尽量避免复杂滤镜和过多节点；保留原PNG作为效果与退回参考，不批量替换。
3. 角色与文本、伤害数字/效果标识不得互相遮挡；只消费原事件，不增加投骰、延长战斗或改写HP。暂停/减少动态效果时显示该事件的静态姿态；尚未验证GIF精确暂停能力前，只在独立试作页使用。

## 比较方法与门禁

同一候选同时生成SVG及按同一尺寸栅格化的PNG，控制画面、视口和显示面积；另与原背景比较，但明确后者画面质量/风格并非等价，不能只报缩小后的体积优势。记录编码字节、HTTP传输（含压缩）、解码/显示时间、重复样本、节点及滤镜数量，观察持续渲染/动画开销和内存估计。GIF另记录帧数、时长、调色板、透明边缘和静态poster大小。

在桌面与390px、正常及减少动态模式验证；如用CPU/网络节流，注明模拟条件，不冒称真机或实际移动网络。复用场景用冷/热缓存分别比较，给出样本范围及噪声，不凭单次时间作结论。交付截图、独立样品及原始JSON，保留原资产和回退。
