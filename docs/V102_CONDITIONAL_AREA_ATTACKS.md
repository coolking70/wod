# v0.102 群攻按实际候选数量决策

补齐原始“按条件特殊技能→基础行动后备”的战前构筑：群攻可选至少2/3名可攻击单位才施放。保持所有旧方案默认关闭，不改技能伤害、成本或奖励。

数量按原目标规则的第一组存活候选计算，封顶技能上限；不跨阵位凑数，不为寻找更多目标自动换阵位。免费计数不用战斗随机数；不满足时不付款、不标记once、继续原后备。含条件的阶段每个新回合从首条重查，额外行动仍受round/once及原轮转限制。旧窗口、用料底线、装备/资源资格照常先检查，自动救护与道具照常独立。

数量只保证可选择人数，不能保证命中/击倒/省料。疗所正常seed2在数量2条件下仍耗尽符纸，这一反例保留。切换到不支持数量条件的技能会清理该参数，0规范为未设置。逐房覆盖、伙伴自定义、实际出征卡、方案册、履历、用料表、默认回放与实际后备来回跳转贯通。

验证：738项完整测试通过。42份旧完整原始报告与v0.101逐字段相同，无排除。36个预先固定输入（三路线、射手/潮术师、0/2/3条件、两种子）均通关且六人生还，仅为有限输入，不称全局升级。真实三次出征：修道院seed1潮术师9次后备；明确分配重盾并付20XP培养后，疗所seed2数量满足而无数量后备；钟楼seed3射手19次后备带回8箭。最终445金币、完整桌面/390px公会与API相同，历史重演不领奖。

边界单测含实际击倒后转单体、敌方第二回合召唤后首次满足once、候选不足不推进战斗RNG（与仅后备的攻防/队员资源逐字段相同）、只计存活第一阵位、群攻只付一次、额外行动、缺后备真实空过、严格参数和计划持久化。初始测试误以为每路线都会出现数量不足、误用了不存在的召唤技能ID；分别改为实际9/0/19行为及有效sentinel夹具，保留初始失败，未弱化生产校验。

桌面/390px新增技能切换清理、编辑器宽度、普通回放证据跳转/返回通过；v101浏览器回归通过。运行入口105模块/122引用检查通过。证据：`docs/V102_PLAYCHECK.json`、`tests/v102.test.mjs`、`scripts/check-v102.mjs`、`scripts/browser-v102.cjs`、云端`/workspace/wod-evidence/v102`。
