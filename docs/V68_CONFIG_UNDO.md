# v0.68：配置撤销同时恢复本次伙伴职责

2026-11-05。从v0.67 `3ee8714`干净工作树、441测试基线继续，本地分支`feature/v068-companion-config-undo`。用户要求优先修复撤销后仍处于自定义的实际职责。

## 修复与操作边界

过去四个入口会先把伙伴从托管切为自定义，再更新草稿；撤销只恢复草稿，实际出征仍用自定义。现在实际队员编辑、共享材料/协作行编辑、加入已学高阶指令、历史单人战术复用都保存同一次配置与伙伴职责变化。在方案管理点击“撤销配置与伙伴职责”会恢复原配置及该次变动的职责，并明确显示涉及姓名。

撤销只存旧配置与职责差量，不存整个公会旧快照。期间真实训练、课程、装备、经验、金币、仓库与其他伙伴的新职责保持当前状态；实际出征仍按当前个人资产覆盖实验草稿。旧职责键原本缺省时精确恢复缺省。原本自定义、主角或普通方案载入继续只撤销配置。

待结算、新远征、主角/出战名单变化或涉及职责已另行调整时拒绝整个撤销，不部分恢复配置，也不消费记录。其他页面改公会时先拒绝覆盖，重新读取且目标状态仍兼容才可重试；其他页面改准备配置时提示先导出草稿并刷新。没有增加多级、跨刷新或出征/奖励撤回；本页面会话仍只有最近一次载入槽，新的普通载入覆盖它，不自动恢复更早职责。

## 写入失败与限制

有职责变化的应用和撤销先核对两份存储文本，再写准备配置、公会职责。准备配置先写失败则不写公会；公会后写失败则回退准备配置，内存和撤销记录保持不变供重试。回退本身也失败时明确显示保存和回退均失败，要求先导出草稿/公会备份；不能把这种情况称为已恢复。

这是同步本机写入的失败补偿，不是浏览器崩溃时的跨键原子事务。未增加持久事务日志、多标签锁或崩溃恢复；普通配置独立保存仍沿用原提示。未调整战斗、奖励、成长经济、普通技能自由搭配或后期独立进阶。
