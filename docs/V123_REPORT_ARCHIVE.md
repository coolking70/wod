# v0.123 关键战报收藏

## 解决的实际问题

v122的真实公会已完成20次远征，普通履历只保留最近20条。正常第21/22次会分别移除第1次钟楼归来与第2次邮路失败；此前只存方案并按当前规则重演，不能永久查看当时收藏到的完整事件。本阶段增加主动选择、有容量上限的关键战报收藏，战斗引擎、关卡、技能、装备和奖励均不变。

在查看正式待领取、已领取但仍打开的正式战报，或最近履历重演时，填写1–40字名称并冻结完整JSON报告。源分别标记pending/claimed/history；history明确是**按收藏时规则重演后冻结**，不能称为当年原始执行日志。一次远征只收藏一份，不能用重命名覆盖原事件；删除后才可重新收藏。

## 玩家操作与边界

- 最近履历仍滚动保留20次；收藏独立保留最多6份。公会履历显示名称、容量、回看/导出/载入战术/改名/移除。
- 专用只读界面按房间、事件、时间线及前后步进回看当时生命、法力、效果、补给、完整事件字段与原方案/队员统计。所有外来文字转义；不调用当前规则重演，也不放正式领取或出征按钮。
- 导出完整快照格式`wod-report-snapshot`，供独立保存/核对；不提供单独快照导入或领奖入口。整档及公会备份均携带收藏。
- 载入战术只用于下次调整，正式出发仍取**当前公会实际装备、培养、本人和托管职责**，并分配新的正常种子。旧编辑方案中展示的历史装备不授予真实资产。
- 名称变更只改标题；移除只删选定收藏。收藏/回看/导出不新增金币、经验、首通或战利品，待领取的实际远征仍须从正常战报结算一次。

## 存储与验证

原始大报告约2.9–6.9MB，本阶段四份均逐字段冻结；使用浏览器原生gzip压缩并记录原始UTF8长度、压缩长度和SHA256，合计base64正文上限800000字符。单份原始上限12MB，配置JSON上限100000字符，最多20000事件/8房/每事件40单位，解压按声明值和12MB双重流式截断。不是把所有历史自动存满，也不增加服务器或新依赖。

打开、导出单份快照、载入战术及两种备份导入会核验内层解压长度、摘要和完整报告结构。整档仍校验外层摘要；即使篡改后重新算外层SHA，损坏内层仍在写入前拒绝。单独公会导入允许8MB文件并同样验证全部内层快照。无收藏的旧公会不新增必填字段，不需要迁移。

压缩/读取属于异步操作，保存前核对公会原始存储值；载入战术还核对准备配置。另一页修改则拒绝覆盖；存储配额失败保留原存档。已有整档四键事务及回退保留。gzip不同实现可能输出不同合法字节，验收独立gunzip并核对原始SHA和**全部解码报告**，公会比较只排除已验证的压缩表示及对应压缩长度，其他所有字段严格比较。
