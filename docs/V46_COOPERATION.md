## 实现

- `dist/expedition-cooperation.mjs`：只读逐房协作投影与视图。使用实际角色ID和既有覆盖选择规则；展示启蒙/战技的正式队员候选、同名增益重叠、每位药师的范围/阈值/优先级、救护重叠与无人覆盖、共享药草使用者。不会把两名药师的药膳配置当作必定扣两份药草。
- 准备页部署桌读取当前草稿；公会出征核对读取 `readiness` 经过伙伴职责及公会资产处理后的实际配置。界面明确两者来源不同。切换核对范围不修改配置、金币、经验、装备或库存，不阻止本来合法的出征。
- 每房提供定位队员与房间的编辑入口。公会入口先保留当前实际指令，再把所选托管伙伴切为自定义，避免丢掉已应用职责的救护阈值；改动由玩家在编辑器内完成。既有战报用料账本、证据定位、冻结A和改配闭环继续复用。
- `scripts/companion-cases.mjs`、`scripts/sample-v46.mjs`：固定配置的独立实验，不读取或发放公会资产；保存逐次结果、实际支援受益者、逐房逐人药草/救护/跳过/空过、敌方有效治疗和分支结果。

这是静态配置核对。覆盖候选不模拟指令轮转、法力/耗材、同名效果先后、倒下、召唤物或实际施放成功；没有胜负预测或自动配装。

## 288次受控对照

运行 `node scripts/sample-v46.mjs`。9方案 × 2训练档 × 2通路 × 种子1–8；每方案32次。均为风暴、尝试解封、前两场预留2符纸、职责分工、12药草/14符纸/10箭矢。训练档沿用v0.45：未训练，或每人专修+2/防御专修+2（6点）。装备、道具、专修、站位和其余指令在同阵容同训练同通路内固定。

原阵容分别只移除启蒙、只移除战技、移除两者。双药师固定奥林替换塞恩，沿用v0.45候补自身默认装备/道具/专修；分别只修改两名药师的普通目标（治疗者→后排备用）、救护优先级（优先自保）、治疗范围（露弥中央/奥林后排），再组合目标与范围。分区组不改站位，前排阿瑟无人救护；这是有遗漏的明确取舍，不是完整分区推荐。

两种阵容间含角色、道具和专修差异，不能当作纯职业强弱估计。移除指令也改变辅助时序与后续动作；共同种子不保证每个动作使用相同随机数。固定小样本不等于总体胜率。

浏览器脚本 `scripts/browser-v46.cjs` 需要外部已安装的Playwright和Chromium，游戏本身不依赖它们。服务启动后可复跑：

```sh
python3 -m http.server 8000 --bind 127.0.0.1 --directory dist
# 另一终端；按实际安装位置指定可选浏览器工具：
WOD_PLAYWRIGHT_MODULE=/path/to/playwright \
WOD_CHROMIUM_PATH=/usr/bin/chromium \
WOD_EVIDENCE_DIR=/tmp/wod-browser-v46 \
node scripts/browser-v46.cjs
```

`WOD_BASE_URL`默认 `http://127.0.0.1:8000`；不使用现有个人浏览器配置，两个测试上下文在结束时关闭，不导出存档。当前云端借用预装Playwright，只读取其安装目录。
