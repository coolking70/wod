# v0.69：把明确预览的草稿指令用于公会出征

2026-11-05。基线为v0.68 `e08585a`干净工作树与已验证453测试；未把旧测试当作本轮新跑。当前分支`feature/v069-draft-command-bridge`。

## 解决的问题

从协作依据、用料账本或普通复盘进入战报改配后，准备页确实改变了，但已应用伙伴职责仍会接管预备/普通/救护指令。此前只有提示，没有直接采用这次改配的入口。现在实际托管伙伴的编辑器提供预览：左侧列出当前实际有效指令，右侧列出将采用值，用户明确应用后才切自定义。预览和进入编辑都不自行改职责。

只复制该人的预备、普通、救护三类指令。保留实际专修、属性、防御专修、站位、防御、道具种类/策略、装备、永久培养、后期进阶与经验；不从草稿授予资产、课程或培养。其他队员的草稿与实际配置保持本次应用前的状态。

本房采用先保留目标当前实际职责，再写选定房间覆盖，其他房间不会退回此前被托管忽略的草稿。默认采用只替换默认三类指令，保留实际逐房覆盖，其余房间继承新默认；不会顺带复制草稿的其他逐房覆盖。这里保留的是应用前当前实际状态，不声称撤回更早“载入整份战报”对草稿的影响。

复用v0.68的配置/职责撤销及成对保存失败补偿。应用后仍定位原队员/房间；撤销恢复应用前草稿和本次职责，期间资产保持当前值。原始战报和A快照不改，不重发奖，不复用历史出征种子。

## 状态与边界

当前草稿和公会必须都包含目标，指定房间必须属于当前准备路线。后台重算预览、验证课程、待结算与过期签名；不信任候选返回值中的伪造配置或公会。跨页公会/配置写保护与存储失败补偿沿用v68。目标本来是自定义或我的英雄时不显示这个托管入口，普通编辑直接采用准备页指令。

预览按resolveHeroPlan展示完整有效指令，避免用“继承默认”遮住真正的托管命令；同时标出相同行。采用本房会写入显式覆盖，即使其中某一阶段当前值相同。没有增加胜负预测、贡献评分、自动优化或新战斗规则。
