# v0.12 回廊救援

在封库试炼第二房间进场时，先处理回廊伤员，再处理沉钟机关。保持战前选择、自动执行、只读回放。新增配置rescueApproach；旧版迁移为pass，不自动消耗资源。

|策略|条件与费用|后果|
|---|---|---|
|直接赶路|无|不检定、不变更物资|
|拾取遗落药草|无|固定获得2药草，不救治|
|救治受伤信使|药师存活且共享药草≥3|扣3药草；治疗技能检定难度70，成功获得4符纸+4箭矢，失败无所得|

救治不额外支付战斗治疗法力、不占行动、不回复队员生命、不复活角色。缺药草或药师倒下时不付费、不检定。检定使用治疗技能实际均值，因此训练、专修与属性均有效；使用独立种子流，不消耗沉钟与战斗随机序列。拾取为低风险补给选项，赶路保留旧方案兼容；当前没有声望或时间系统。

材料立即记入共享库存。60份是战前携带预算，不是途中库存上限。沉钟事件的sourceRescueEventId链接本次救援记录；已有末房route记录仍链接沉钟，实现救援→材料变化→沉钟→末房后果的追溯。报告保留物资前值、净变化和后值，以及救治检定与等级来源。

## 验证

94项测试通过，新增7项：迁移与校验、无条件分支无随机消耗、救治成功/失败费用、补给解除沉钟缺料、无队员治疗或复活、独立随机、触发范围、差异与复盘及只读投影。

浏览器实测：载入救援事件链，种子1，露弥均值57、投点71成功；药草15→12、符纸19→23、箭矢13→17；沉钟随后扣2符纸，成功投点90。追溯按钮正确返回救援。种子42救治投点46失败，仅扣3药草。截图见V12_RESCUE.jpg。

## 范围和下一步

本版无新增CG，沿用场景与头像，新增事件策略及物资面板。仍为单次远征、固定三房间，无后端、自由地图或长期NPC系统。未完成多种子平衡评估；默认药师均值57低于难度70，不应将示范成功种子视为通常收益。

下一步应整理事件链总览与队伍构筑入口、减少准备页长度，并开展小规模多种子策略对照；随后补充伤员场景CG。暂不继续堆叠独立事件，以免规则增加但决策难以理解。
